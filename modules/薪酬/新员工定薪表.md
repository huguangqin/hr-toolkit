模块 / 场景：薪酬发放 — 入职定薪
工具名称：新员工定薪与 Offer 薪酬测算表
适用场景：给候选人发 offer 前定薪、谈判僵局时找空间、避免"熟人价""拍脑袋价"造成内部倒挂
操作步骤 / 方法：
1. 定锚：用薪酬调研对标表的该岗市场分位（P25/P50/P75）作基准
2. 看内部：查宽带矩阵里该级的 min/mid/max，定薪不得超 max、尽量不破 mid 太多
3. 算空间：在"市场 P50 × 公司预算 × 级内带宽"交集里找落点；谈判余地 = max - 初报价
4. 拆结构：谈总包时，用"固定+签字费+期权"组合满足期望，而非一味加底薪
5. 防倒挂：定薪后查同级在职者 CR，避免新人比老员工高太多却不告知

模板 / 话术（可直接复制）：
```
【新员工定薪测算表】
岗位：______  对标市场：P25__ P50__ P75__
公司该级带宽：min__ mid__ max__

候选人期望：______
可给区间（不超max）：________ 至 ________
建议落点：________（理由：贴近P50且留15%涨薪空间）

结构组合（总包不变，满足期望）：
  方案A 纯底薪：______（简单但贵，易倒挂）
  方案B 底薪+签字费：底薪______ + 一次性签字费______
  方案C 底薪+期权：底薪______ + 期权______股（长绑）
最终选：______

倒挂检查：同级在职者当前薪 ______，新人 ______，差 ______%（>15% 需主管审批）
```

注意事项 / 常见坑：
- **"熟人价/上家价"定薪**：完全按候选人上家薪资或"他开口多少"定，不看市场也不看内部，极易造成新人比老人高 30% 的倒挂，老人发现后集体心态崩。
- **谈判只加底薪 = 埋雷**：底薪是刚性成本，谈判全加底薪，后续每年涨薪基数变大、总成本失控。善用"签字费（一次性）+ 期权（长期）"满足期望。
- **超 max 要升级审批**：候选人要价超过该级 max，不能私自给，需升一级或特批，否则破坏带宽秩序。
- **offer 写"税前"且结构清晰**：写清固定/浮动/发放条件，避免入职后因"说好的奖金没写"起争议。
- **倒挂要管理而非掩盖**：新人高薪难免，但主管要知会老人"你明年调薪路径"，并让新人薪酬保密，别让倒挂变成公开伤口。
