模块 / 场景：薪酬体系设计 — 薪酬等级
工具名称：宽带薪酬等级矩阵（职级 - 薪酬带宽）
适用场景：减少管理层级、给员工"不晋升也能涨薪"的空间、控本时封顶、多通道（管理/专业）发展设计
操作步骤 / 方法：
1. 定职级序列：管理序列 M、专业序列 P（可再分技术/产品/职能），每序列分若干级
2. 定每级"带宽"：即该级薪酬下限 min、中位 mid、上限 max，带宽% = (max-min)/min
3. 定级差：相邻级 mid 的差额比例（一般 15%-30%）
4. 算重叠度：上级 min 低于下级 max 的部分占下级带宽的比例（一般 20%-40% 为宜）
5. 把现有人套入矩阵，标出"触顶（在 max 附近）"和"触底（在 min 附近）"人员，分别定调薪/晋升策略

模板 / 话术（可直接复制）：
```
【宽带薪酬矩阵（示例：专业序列 P）】
职级   min     mid     max     带宽%   重叠度(对下级)
P1    6k      8k      11k     83%     —
P2    9k      12k     16k     78%     P2min<P1max → 重叠
P3    13k     17k     23k     77%     27%
P4    18k     24k     33k     83%     22%
P5    25k     34k     46k     84%     24%

读法：P3 员工在 17k(mid) 为市场合理位；涨到 23k(max) 触顶，再涨需升 P4；
     想横向调岗到 P4 同级，因重叠 22% 薪酬可平移不降。
```

注意事项 / 常见坑：
- **带宽不是越宽越好**：带宽 > 100% 会失去等级意义，员工不知自己在该级什么位置；50%-100% 是常用区间。
- **mid 要对齐市场 P50**：mid 是"健康薪点"，低于 P50 的级会系统性流失人。
- **重叠度过低 = 回到窄带**：重叠 < 10% 等于没做宽带，员工不晋升就涨不动；过高（>50%）则级别失序、同级薪酬差太大引发攀比。
- **"触顶不晋升"要预设规则**：员工到 max 后，要么升职级、要么用特殊津贴/项目奖突破，否则会卡死流失。提前在制度里写清。
- **带宽要配晋升标准**：宽带给了涨薪空间，但"凭什么涨"必须靠职级晋升标准/能力认证，不能主管随意调，否则变成普涨。
