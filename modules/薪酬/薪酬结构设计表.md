模块 / 场景：薪酬体系设计 — 薪酬结构
工具名称：薪酬结构设计模板（固定 + 浮动 + 津贴）
适用场景：从零搭薪酬包、销售/研发/职能差异化设计、薪酬改革时重新切"固定与浮动"的比例
操作步骤 / 方法：
1. 定薪酬总额：根据人力成本预算与人效目标，框定总盘
2. 拆结构：固定部分（底薪 + 岗位工资 + 津补贴）、浮动部分（绩效工资 + 奖金/提成）、长期部分（股权，另见股权激励框架）
3. 按岗位价值创造方式定固浮比：价值越难过程量化、越靠长期，固定占比越高
4. 定发放节奏：固定按月、绩效按季/年、奖金按达成节点
5. 做成本测算：同一总包下不同固浮比对离职率、积极性的影响

模板 / 话术（可直接复制）：
```
【固浮比参考表（同薪不同命的关键）】
岗位族    固定:浮动   底薪占比   适用逻辑
高管      4:6        40%       对长期结果负责，强浮动
销售      3:7~2:8    30%       价值=业绩，高浮动高上限
研发      7:3        70%       价值=持续产出，需稳定底数
职能(财务/HR) 8:2    80%       价值=支撑，波动小
产线工人   8:2        80%       计时/计件已含激励

【单岗结构拆分示例】某研发工程师 年包 30万
  固定 21万(70%) = 底薪 17.5万 + 岗位工资 3.5万
  浮动 9万(30%)  = 季度绩效 6万 + 年度项目奖 3万
```

注意事项 / 常见坑：
- **销售不能"全浮动"**：完全没底薪招不到人，也留不住淡季的销售；保留基础生计数（当地最低工资 2-3 倍）才稳。
- **研发浮动别绑个人 KPI 太死**：研发价值在协作与长期，绑个人短期 KPI 会诱发抢功、拒协作；浮动应含"公司/项目绩效"成分。
- **同岗不同结构 = 暗雷**：同样"工程师"头衔，A 固定 80%、B 固定 50%，哪怕总包一样，B 会觉得自己被"销售化"、没安全感。结构要按"岗位族"统一，不按"人"定制。
- **浮动部分要"算得出、拿得到"**：规则模糊的浮动工资 = 变相降薪，员工会用脚投票。提成/奖金公式必须事前白纸黑字。
- **津补贴别当固定发**：交通/餐补本是可调的，若写成固定必发，后续改革极难动，会变成刚性成本。
