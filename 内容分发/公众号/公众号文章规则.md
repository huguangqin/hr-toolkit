# 公众号文章规则（hr-toolkit 精编）

> 本文件是「公众号精编」工序的操作规则。GitHub 母本是单一事实来源，公众号文章全部由母本工具表加工而来，不得各写各的。

---

## 一、定位与分工

- 公众号 = GitHub 母本的**精编版 + 使用解读 + 真实案例**，目的是把"可抄的作业"讲透、让 HR 愿意收藏转发。
- 知乎 = 引流，公众号 = 沉淀，GitHub = 母本。三者口径一致。
- 选题来源：① 近期 HR/劳动法热点（借势）② 母本某张工具表的落地解读 ③ 二者结合最佳。

---

## 二、标题规则（核心，2026-07-29 新增）

**标题必须制造悬念、激发好奇心。** 公众号打开率 80% 取决于标题，平铺直叙的标题等于白写。

可用的悬念手法（可叠加）：
1. **反常结论**：把反直觉的事实摆出来 —— "试用期说开就开？一个判例让公司赔了 6 个月工资"
2. **数字冲击**：具体金额 / 倍数制造痛感 —— "离职被索赔 180 万""开除反而赔了 8 万"
3. **冲突 / 反转**：预期 vs 现实 —— "员工手册发了 800 封邮件，仲裁却判'没公示'"
4. **代入式提问**：让读者觉得自己"中招" —— "怀孕女员工天天迟到，能开吗？"
5. **损失规避**：不看的代价 —— "HR 再不搞清楚就亏了""99% 的公司都栽在这个坑"
6. **热点钩子**：绑最近热点 —— "7月1日新规落地""小鹏近千万索赔案"

**硬约束**：
- 标题不得标题党（内容与标题必须严丝合缝，不能靠夸张骗点击）。
- 悬念来自"信息差"，不是"隐瞒信息"。读者点进去必须真有干货，否则掉粉。
- 禁止「震惊体」「不转不是中国人」等低质套路。

---

## 三、低创作度规避规范（平台红线，务必遵守）

公众号平台明确不推荐低创作度内容，以下行为会导致限流甚至处罚：
1. 同质化、频繁发高度相似内容、缺信息增量；
2. 搬运 / 抄袭 / 洗稿 / 大篇幅引用他人、重复发布、整体创作度低；
3. 信息量不足、疑似无法提供有效价值；
4. 低价值 AIGC：支持技术辅助创作，但不鼓励用新技术直接生成、批量制造低信息量内容。

**我方做法（铁律）**：
- 每篇**原创、有信息增量**，给可抄模板 / 真实场景 / 具体观点。
- 带人味：具象场景、真实数字、明确主张，杜绝"首先其次最后"空壳与洗稿式堆砌。
- 法规引用必须注明来源与时效（如"据《超龄劳动者基本权益保障暂行规定》2026-07-01 施行"），不编法条。

## 四、排版规范（技术约束，源自微信草稿接口特性）

1. **全内联样式**：微信草稿接口会**丢弃 `<style>` 块**，只认元素上的 `style="..."`。所有样式必须写成内联，否则只剩 `<b>/<strong>` 生效。
2. **正文不配图**：正文 `<img>` 在草稿接口下不稳定，统一不放正文配图；视觉靠排版与封面承载。
3. **封面必填**：草稿接口强制要求 `thumb_media_id`（列表封面）。每篇文章配一张独立封面图，文件名须含 html 词干或"封面"字样，供 `push_to_mp.py` 精准匹配（避免旧图错配）。
4. HTML 结构：`push_to_mp.py` 读取 `<body>` 内联内容推送；内部作者备注用 `<p class="footnote">` 包裹，发布前自动剔除。

---

## 五、推送规范

1. **仅入草稿箱，不群发**：用 `push_to_mp.py` 推送，脚本按标题幂等（已有则原地 update）。
2. **实际群发前需大勤确认**：草稿箱是内部动作，可大胆；群发 / 发布是外部动作，须确认。
3. **凭据不落库**：`WX_APPID` / `WX_APPSECRET` 仅以环境变量临时传入，不写入代码或记忆。
4. 推送后到后台草稿箱核对：正文顶部若不想显示封面，手动勾"不显示封面"。

## 六、一篇文章的产出清单（自检）

- [ ] 标题用了第二节的悬念手法之一，且与内容严丝合缝
- [ ] 绑定了母本某张工具表（文末可引导去 GitHub 取全套）
- [ ] 给了可抄模板 / 清单 / 话术（不止讲道理）
- [ ] 用了真实场景或具体数字，有信息增量
- [ ] 全内联样式，正文无 `<img>`，配独立封面 png
- [ ] 法规引用标注了来源与时效
